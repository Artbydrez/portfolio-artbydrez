## Design Specificity Verdict

**LLM assessment**: Specific and improvable. Four of five round-1 fixes are concrete and fully land live. The copy rewrite is consistently threaded through headline, subtitle, form, and both CTAs rather than a surface word-swap. The accessibility fix is where specificity breaks down: it solved the literal ask (tabindex/role/Enter-Space on three selectors) but missed the actual requirement — reaching those elements by pressing Tab — because that path was never tested end-to-end in round 1.

**Deterministic scan**: Same 2 findings as round 1 (Helvetica-Neue false positive on `overused-font`; negligible `layout-transition` on a 5px `#cursor-dot`). Em-dash count dropped 45→35, and of those 35, **zero are in visible prose** — all remaining are in code comments, the `<title>`/`og:title` tags, or `alt=""` attributes, which is appropriate placement. The ▪ square-glyph replacement was independently confirmed (39 instances) and reads as intentional on both assessments. The browser overlay repeated its round-1 findings on low-contrast text (`3.4:1 on #666666/#0c0c0c`, need 4.5:1), undersized UI text (9-10px on several form/meta labels, below the 11px floor), and a skipped heading level (`h1`→`h3`) — none of these were in scope for this round's fixes, so their persistence isn't a regression, but they're still open.

## Priority Issues

**[P0] Keyboard focus reaches invisible off-screen pages — the keyboard fix doesn't make the site navigable**
- Why it matters: `.page` sections sit side-by-side and move off-screen purely via `transform`; nothing sets `aria-hidden`/`inert`/`tabindex="-1"` on the inactive ones. Confirmed with real Tab keypresses from the Home page: focus moves from the CTA button straight into `.po-panel` elements belonging to the Portfolio Overview page, which is 100vw away and not visible at all — with no focus ring appearing anywhere on screen. A keyboard user can now activate something once they land on it, but has no sane way to land on it, and no visual trace of where focus is. This is more disorienting than simply unreachable, and it directly undercuts PRODUCT.md's own "the site's form should itself demonstrate attention to detail" principle for exactly the visitor type it's meant to reassure.
- Fix: in `goTo(index)`, set `inert` (or `tabindex="-1"` + `aria-hidden="true"`) on every `.page` except the active one, clearing it from the newly active page.
- Suggested command: `/impeccable harden`

**[P0] The Nebula FC story page is completely orphaned — no link anywhere leads to it**
- Why it matters: `page-project-nebula` (index 11) holds the richest content on the site — full club backstory, logo-symbolism breakdown — and has its own back-link and keyboard-escape wiring, but nothing in the entire file calls `goTo(11)`. Arrow-key/swipe paging is capped before reaching it too. The only way in is typing `#11` directly in the address bar. This is pre-existing (not caused by this round's work), but it means the single deepest demonstration of "souci du détail" on the whole site has likely never been seen by a recruiter using the site normally.
- Fix: add a visible entry point — e.g. a "Voir l'histoire complète du club →" link on the Travail de fin d'étude overview page (`goTo(5)`) that calls `goTo(11)`.
- Suggested command: `/impeccable clarify`, then `/impeccable audit` to check whether any other `goTo()` target has the same orphaning problem

**[P2] Form errors are shown by color and motion only, not text**
- Why it matters: invalid fields get a red border and a shake animation; there's no inline error text, no `aria-invalid`, no `aria-describedby`. Fails for colorblind users and is invisible to screen readers — a non-sighted recruiter gets no indication anything went wrong beyond the form silently not submitting.
- Fix: add a short visible error string under each invalid field ("Ce champ est requis") and toggle `aria-invalid="true"` alongside the existing shake.
- Suggested command: `/impeccable harden`

**[P2] Low contrast and undersized text persist on several small labels (detector-confirmed, both runs)**
- Why it matters: `#666666` on `#0c0c0c` measures 3.4:1 against a 4.5:1 requirement, and several functional labels (form fields, project meta) render at 9-10px, below the 11px legibility floor the detector flags. Same signal in both critique rounds — not a regression, but not yet addressed either.
- Fix: audit remaining `--text-dim`/small-label usages for contrast and bump the smallest instances to ≥11px.
- Suggested command: `/impeccable audit`

**[P3] The "2026" timeline entry doesn't read as current**
- Why it matters: "2026 · Infographiste ▪ Line Up Team" is formatted identically to the closed-out entries below it, so a recruiter skimming in seconds (per PRODUCT.md's own operating context) may not register it as an active role.
- Fix: add a small "· En cours" marker or distinct treatment on the top entry only.
- Suggested command: `/impeccable clarify`
